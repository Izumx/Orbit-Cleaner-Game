## 1. Что это

OrbitClean — интерактивная браузерная 3D-платформа про космический мусор. Пользователь видит фотореалистичную вращающуюся Землю, вокруг которой по **реальным орбитам** летает рой из 10 000+ отслеживаемых объектов (спутники, ступени ракет, обломки). Кликая на объект, игрок открывает карточку с реальными данными об этом объекте и вопросом, привязанным к этим данным. Правильный ответ «очищает» объект, начисляет очки и снижает индикатор перегруженности орбиты (Kessler-meter).

**Цель:** наглядно показать масштаб проблемы космического мусора и синдрома Кесслера, совмещая «залипательный» визуал с образовательной механикой.

## 2. Технический стек

| Слой | Технология | Зачем |
|------|-----------|-------|
| Сборка | Vite + React + TypeScript | Быстрый dev-цикл, hot reload |
| 3D | react-three-fiber (R3F) + drei | Декларативный three.js, готовые камеры/контролы/звёзды |
| Эффекты | @react-three/postprocessing | Bloom, vignette — «киношность» |
| Орбиты | satellite.js (SGP4) | Расчёт позиций из TLE |
| Параллелизм | Web Worker | Расчёт орбит вне главного потока |
| Данные орбит | CelesTrak (TLE/GP) | Источник каталога отслеживаемых объектов |
| Текстуры Земли | NASA Blue Marble | Дневная/ночная карта, облака, рельеф |
| Бэкенд/БД | Supabase (Postgres + Auth) | Аккаунты, прогресс, лидерборд |

**Важно про данные:** канонический каталог объектов — это CelesTrak / Space-Track (US Space Force), **не NASA напрямую**. От NASA берём только текстуры Земли. В UI/описании формулируем источники честно.

## 3. 3D-сцена

Земля:
- Дневная текстура NASA Blue Marble
- Ночная сторона со светящимися городами (emissive-карта, проявляется по линии терминатора)
- Отдельный слой облаков (медленное независимое вращение)
- Bump-карта рельефа
- Двигающийся терминатор день/ночь

Атмосфера:
- Fresnel-шейдер — мягкое голубое свечение по краю планеты (ключевая деталь «дорого»)

Окружение:
- Звёздное небо (реальная карта звёзд или drei `<Stars>`), лёгкий параллакс

Рой объектов:
- 10 000+ объектов через `InstancedMesh` (один draw call, цель 60fps)
- Цвет/категория по типу: спутник / ступень ракеты / обломок
- Glow-частицы

Камера:
- Авто-вращение в покое
- Плавный «подлёт» к выбранному объекту при клике (стретч)

Постпроцессинг:
- Bloom (свечение объектов и огней городов)
- Vignette (затемнение по краям)

## 4. Поток данных и производительность

1. При загрузке: fetch TLE с CelesTrak → кэш (localStorage / память)
2. Парсинг TLE → массив объектов с орбитальными элементами
3. **Web Worker** считает позиции всех объектов через SGP4 на пониженной частоте (~5–10 Гц) — это самая дорогая операция, её нельзя гонять каждый кадр
4. Главный поток интерполирует между обновлениями воркера и обновляет матрицы инстансов каждый кадр (обновление 10k матриц на главном потоке — дёшево; дорог именно SGP4)
5. Клик → один raycast по `InstancedMesh` → `instanceId` → выбор объекта

**Пикинг мелких точек:**
- Подсветка объекта при наведении (hover)
- Щедрый радиус попадания / увеличенный hit-area, т.к. точки мелкие
- При необходимости — GPU-пикинг (рендер instanceId в отдельный буфер) как fallback для точности

## 5. Геймплей

**Карточка объекта (при клике):**
- Реальные данные ЭТОГО объекта: название/NORAD ID, тип, год запуска, высота (perigee/apogee), скорость, оценочное время схода с орбиты
- **Вопрос, сгенерированный из этих данных** — шаблоны, параметризованные типом объекта и высотой. Это позволяет дать релевантный вопрос для любого из 10k объектов без ручного написания 10k вопросов.
  - Пример: объект на 800 км → «На такой высоте обломок сходит с орбиты ~200 лет. Это больше или меньше, чем у МКС на 400 км?»

**Цикл:**
- Правильный ответ → объект «пойман» → эффект исчезновения → +очки
- Неправильный → объект остаётся, без очков (можно дать ограниченные попытки/подсказку)

**Kessler-meter:**
- Индикатор перегруженности орбиты (можно по высотным поясам)
- Снижается по мере очистки — связывает геймплей с реальной проблемой синдрома Кесслера

**Прогресс:**
- Очки и список пойманных объектов сохраняются
- Общий лидерборд игроков (Supabase)

## 6. Структура компонентов (черновик)

- `Scene` — корень R3F-канваса, освещение, постпроцессинг
- `Earth` — Земля со всеми слоями (день/ночь/облака/bump/атмосфера)
- `DebrisField` — `InstancedMesh` роя, обновление матриц, raycasting
- `useOrbitWorker` — хук-обёртка над Web Worker (SGP4)
- `tle/` — загрузка, кэш, парсинг TLE с CelesTrak
- `ObjectCard` — карточка с данными объекта + вопрос
- `questions/` — генератор вопросов из атрибутов объекта (шаблоны)
- `gameState` — очки, пойманные объекты, Kessler-meter (store, напр. zustand)
- `KesslerMeter` — UI-индикатор
- `Leaderboard` — UI лидерборда
- `supabase/` — клиент, auth, чтение/запись прогресса
- `About` / футер — авторство

Каждый модуль с одной зоной ответственности и чётким интерфейсом, чтобы тестировать и менять независимо.

## 7. Объём работ (MVP → стретч)

**MVP (обязательно к дедлайну):**
1. Крутая 3D-Земля: текстуры NASA + атмосфера + звёзды + постпроцессинг
2. Рой 10k+ реальных объектов, летящих по орбитам (CelesTrak + satellite.js + worker + InstancedMesh)
3. Клик → карточка с реальными данными объекта + сгенерированный вопрос
4. Очки + Kessler-meter (локально, localStorage)

**Стретч (если останется время):**
5. Supabase: аккаунты/nickname + общий лидерборд
6. Подлёт камеры к объекту, звук, доп. визуальные эффекты

**Обоснование приоритетов:** 3D с реальными данными — главный «вау», который продаёт проект жюри. Лидерборд/БД — приятный бонус, но не должен съесть время, нужное на главный экран. Архитектуру (`gameState`) делаем так, чтобы подключение Supabase было лёгким апгрейдом, а не переделкой.

## 9. Открытые вопросы / риски

- **Дедлайн StarDance не зафиксирован** — от него зависит, сколько стретча реально успеть. Проверить правила (соло/команда, дедлайн, критерии оценки) на сайте перед стартом.
- **Производительность пикинга** на 10k+ объектах — заложен fallback на GPU-пикинг.
- **Размер TLE-выборки** — 10k+ объектов: проверить FPS на средней машине, при необходимости снизить или применить LOD/culling.
- **Точность данных** — формулировки источников (CelesTrak vs NASA) держать честными для доверия жюри.
